# WeChat layout

把 Markdown 排成公众号文章，在浏览器预览、复制富文本或导出 HTML。默认使用**保真排版**，无需配置 LLM；接入 LLM 后，可选择使用上游的 AI 增强功能。

本项目是 [DemoJ/md2html](https://github.com/DemoJ/md2html) 的个人 fork，组件设计源于甲木 × 摸鱼小李的 [gzh-design-skill](https://github.com/isjiamu/gzh-design-skill)。新增橙色／墨绿配色、保真模式、文件渲染入口，并修正目录卡片为同排等宽等高。针对手机微信优化了中英文混排列表的字距，代码块保留原始分行、空行和缩进，长行支持左右滑动。

## 先跑起来

建议使用 Node.js 20.19+ 或 22.12+ 的受支持版本。

```sh
git clone https://github.com/huasanai/wechat-layout.git
cd wechat-layout
npm ci
npm run dev -- --host 127.0.0.1
```

打开终端显示的地址，通常是 `http://127.0.0.1:5173/`。在左侧输入 Markdown，右侧实时预览；切换主题后点击「复制到公众号」。**保真模式不需要 API Key，也不需要点击 AI 增强。**

## 排版到底依据什么？

排版由三项共同决定：**Markdown 结构、当前模式、所选主题**。Markdown 决定“这是一段正文、标题还是引用”，模式决定“是否自动补目录、标重点等”，主题决定字号、颜色、圆角、边距与组件外观。

```text
Markdown → 解析标题/正文/列表/引用 → 按当前模式匹配组件 → 套用主题 → 内联样式 HTML
                                                                           ↓
                                                               浏览器预览 → 复制/导出
```

默认保真模式主要执行明确规则，不靠 LLM 猜版式。以下是默认模式的触发方式。

| 你写的 Markdown | 渲染结果 | 是否参与 01、02… 编号 |
|---|---|---|
| `# 文章标题` | 大号文章标题 | 否；建议一篇只用一个一级标题 |
| 普通段落 | 正文，默认 15px | 否 |
| `## 从答案退回问题` | 章节标题 | 是，按文中出现顺序编号 |
| `### 小标题` | 较小的子标题；四至六级也走子标题逻辑 | 否 |
| `## 本期看点` 或 `## 本文看点`，紧跟三项短列表 | 横向看点目录 | 开启「显示目录」时不参与章节编号 |
| `## 写在最后` 等结语类标题 | `∞` 编号与 `THE END` 标签 | 占一个章节位置，但编号显示为 `∞` |
| `> 引用内容` | 主题引用框 | 否 |
| `**重点**` / `==高亮==` / `++下划线++` | 加粗／高亮／下划线 | 否 |
| `---` | 普通分隔线 | 否 |

### 1. 横向“本期看点”怎样触发？

**默认保真模式下，需要明确写出看点标题和三项列表。** 标题文字识别「本期看点」「本文看点」两种，不支持自定义成「这期聊什么」后仍自动识别。

推荐固定使用二级标题：

```markdown
## 本期看点

- 从答案退回问题
- 把假设放到桌面
- 用行动检验判断
```

规则与边界：

- 标题后紧接一个恰好三项的列表；有序、无序都可以，每项只能是一段，不能再嵌套列表。两项、四项或插入正文会报错。
- 当前实现按**标题文字**识别，并非只认 `##` 层级；建议统一使用上面的二级标题写法。标题里的文字也不能多加后缀，例如「本期看点：」不会触发。
- 三个看点来自你提供的列表，不会自动概括，不要求与后面的章节标题逐字相同，也不会自动建立跳转链接。
- 摸鱼绿及个人橙／墨绿配色使用原有目录组件：**三张看点卡＋一张固定的「写在最后」卡**。最后一张是目录样式，不会自动生成结语正文。
- 卡片宽度一致，标题自然换行；最长标题撑起整排高度，其余卡片同步变高。手机上保留横向滚动。
- 没写看点模块，就不自动补目录。关闭设置中的「显示目录」后，已写的看点退为普通标题和列表；此时该二级标题也按普通章节参与编号。

### 2. 中间的 01、02、03 是怎样确定的？

**按正文中二级标题 `##` 的出现顺序计数。** 不需要手写数字；章节文字本身不决定序号。

```markdown
# 文章标题

## 本期看点

- 问题
- 证据
- 行动

## 明确问题
这里显示 01。

### 一个补充说明
子标题不增加编号。

## 寻找证据
这里显示 02。

## 采取行动
这里显示 03。

## 写在最后
这里显示 ∞ 和 THE END。
```

默认显示目录时，「本期看点」不占号，所以后面的「明确问题」从 01 开始。插入、删除或移动一个普通二级标题，后面的编号会随之改变。

不要写 `## 01 明确问题`：程序不会删除你手写的“01”，会同时显示自动编号和原标题中的数字。

### 3. `∞` 只由“写在最后”触发吗？

不只。默认保真模式检查二级标题是否**包含**以下任意文字：

```text
写在最后、结语、结束语、终章、尾声、后记、收尾
```

例如 `## 结语`、`## 写在最后：下一步怎么做` 都会显示 `∞` 和 `THE END`。**无需手动输入 `∞` 或 `♾️`；实际生成的是文字字符 `∞`。**

`## 总结`、`## 小结` 当前不在识别名单中，会继续显示普通数字编号。仅在正文里提到「写在最后」不会触发。

当前程序也不强制结语必须在末尾：中间章节包含上述词也会被识别，且后续章节继续计数。建议只在最后一个二级标题使用结语词；若要调整名单，修改 [`CONCLUSION_KEYWORDS`](src/core/transform.ts)。

### 4. `—— END ——` 和文末说明从哪里来？

保真模式只要有文章内容，就会自动在末尾加一条 `—— END ——`，与有没有结语标题无关。它是装饰性收尾，不需要额外写 Markdown。

署名、关注引导或其他说明，在「设置 → 文末说明」明确填写；留空不添加。保真模式不自动添加上游的“点赞、在看、转发”引导。文末说明会保存在当前浏览器，换文章前可检查是否仍适用。

## 一份可以直接试的完整稿件

```markdown
# 把答案交给 AI，把判断留给自己

> 好的问题，让我们看见自己的假设。

表达清楚与判断可靠，需要分别检查。

## 本期看点

- 从答案退回问题
- 把假设放到桌面
- 用行动检验判断

## 从答案退回问题

先问一句：**我到底要做什么决定？**

## 把假设放到桌面

将事实与解释分开，寻找能改变判断的证据。

> 不急着把解释写成结论。

## 用行动检验判断

把下一步做小，把验证标准说清楚。

## 写在最后

保留自己的判断，也给新证据留下位置。
```

## 保真模式与增强模式有什么区别？

顶部「保真排版」默认勾选。**取消勾选就进入上游增强渲染方式，即使还没点击 AI 增强，渲染规则也已改变。**

| 行为 | 保真模式（默认） | 增强模式（取消勾选） |
|---|---|---|
| 字句与标点 | 保留原字句和标点 | 会规范部分中文标点；纯文本经 AI 转换后可能新增结构 |
| 目录 | 用明确写出的看点标题＋三项列表 | 有至少两个章节且开启显示目录时，从全部章节自动生成；无需另写「本期看点」 |
| 自写的「本期看点」 | 特殊模块，不按普通章节渲染 | 按普通章节处理，可能被计入自动目录 |
| 章节编号 | 普通二级标题按顺序计数 | 一级／二级章节标题按顺序计数，文首文章标题除外 |
| 结语符号 | 结语关键词触发 `∞` 与 `THE END` | 按主题规则，如摸鱼绿及个人配色使用 `///`；英文标签由词典或 AI 决定 |
| 引言 | 原位置的引用框 | 文章标题后的首个引用块可成为引言卡；无开头引用就不生成引言卡 |
| 顶部封面 | 不插入封面图片；在公众号编辑器中手动插图 | 开启显示封面时，生成简单文字封面卡；AI 可补封面文案 |
| 文末 | 自动 END；仅添加你填写的文末说明 | 可能添加署名与默认互动引导；保真模式的文末说明字段不用于此路径 |
| LLM | 不调用；AI 按钮隐藏 | 配置后可主动点击「AI 增强」，不点也可按规则渲染 |

因此，本文的完整示例推荐在**保真模式**中使用。不要在两种模式之间切换后，仍假定目录、结语或文末规则完全相同。

## 接入 LLM 的作用是什么？

**LLM 帮助决定“强调什么、配什么文案”，最终版式仍由主题和渲染代码生成。** 不接入 LLM，也能完成排版、预览、复制和导出。

取消勾选「保真排版」，在设置中填入 Base URL、Model 和 API Key，测试连接后点击「AI 增强」。接口采用 OpenAI 兼容的 `/chat/completions` 协议；实际模型名以你的服务商为准。原生 Anthropic Messages API 不能仅凭更换地址直接使用。

| LLM 能做的事 | 当前程序怎样使用 |
|---|---|
| 找重点词 | 从原文段落选短语，渲染器为匹配到的文字加下划线 |
| 生成英文标签 | 为章节补 `TEST`、`TUTORIAL` 等标签 |
| 辅助引言强调 | 为文章开头已有的引用选择高亮词，并可能提供署名；不凭空生成整段引言 |
| 生成封面文案 | 为顶部 HTML 文字卡生成主副标题、标签等；**不生成 PNG 图片，也不替换独立封面设计** |
| 判断文章类型 | 返回教程、观点、案例等分类，在界面展示 |
| 推荐主题 | 按题材推荐现有上游主题，程序可能自动切换；不保证保留你手动选的橙／墨绿 |
| 纯文本转 Markdown | 检测不到 Markdown 标记时，可推断标题、分段与列表；会替换编辑器文本，建议先留原稿 |

当前代码还解析了 AI 返回的看点推荐序号，但增强模式的目录渲染仍使用全部章节；不能把它理解为“AI 已自动精选三条看点”。

一次 AI 增强通常包含“文章分析”和“主题推荐”两次调用；如果还要先转换纯文本，会再多一次。连接测试也会调用接口，因此并不是“一次点击只请求一次”。

文章片段与 API Key 由浏览器直接发送到你配置的模型服务。Key 和配置保存在当前站点的 localStorage，并非加密凭据库；普通保真排版不向 LLM 发请求。是否允许浏览器直接访问接口还取决于服务商 CORS 设置，调用费用由对应服务商收取。

## 主题与颜色怎样维护？

内置六套上游主题，加两套个人配色：

| 主题 | ID | 主色／特点 |
|---|---|---|
| 画伞 · Claude 橙（默认） | `huasan-claude` | `#c04a1a`，辅助色与浅底同步分层 |
| 画伞 · 墨绿 | `huasan-forest` | `#365B47` |
| 摸鱼绿 | `moyu-green` | `#059669` |
| 红白色系 | `red-white` | `#DC2626` |
| 石墨极简 | `graphite-minimal` | `#52525B` |
| 留白禅意 | `zen-whitespace` | `#4A5D52` |
| 摸鱼票据 | `moyu-ticket` | 绿色票据风 |
| 橄榄手记 | `olive-journal` | 墨黑配橙色 |

两套个人主题在 [`src/themes/huasan.ts`](src/themes/huasan.ts) 维护，直接调用摸鱼绿组件，**只替换 CSS 色值**，不另写字号、边距、圆角与目录布局。

- `primary`：编号、重点词、边线等主色。
- `secondary`：渐变或次级强调色。
- `lightBg`：引用等区域的浅底。
- `lightBorder` / `lightBorderSoft`：下划线、边框等颜色。
- `highlight` / `highlightBg`：显式高亮使用的色板字段；具体组件决定是否使用。

目录等宽等高规则在 [`src/themes/base.ts`](src/themes/base.ts) 的 `toc` 组件，修改后原摸鱼绿和个人配色一起生效。其他主题可以覆盖自己的组件，不能假定它们布局都相同。

## 正文字号、列表、图片与导出

所有主题的默认正文字号为 15px。保真模式的有序和无序列表保留语义、起始序号与嵌套层级；标记在文章左右 20px 留白以内，列表段落不重复缩进。样式随正文内联写入复制结果。

- **封面图片**：本工具不导入本地封面，不上传图片。完整封面由独立工具生成，在公众号编辑器中手动插入。
- **复制与图片**：复制只包含正文富文本，不插入封面占位标记。保真模式的正文图片须使用 HTTPS 地址，微信保存后的可用性仍需核验。
- **批注**：`%%内部备注%%` 不进入文章；存在未决批注时可预览但不能复制、导出。代码中的同样字符按字面保留。处理后从工作稿移除批注，不修改唯一原稿。文首 frontmatter 也不进入正文。
- **外链**：保真模式保留链接地址，但微信可能限制外链点击。
- **导出**：界面导出正文 HTML；文件入口还能输出 Markdown、预览与检查报告。字体与样式尽量随正文走内联样式，不依赖预览工具栏。

程序的本地校验能发现部分标签与样式问题，**不能保证公众号保存后的格式**。首次使用某个主题，请完成：粘贴 → 保存 → 重新打开 → 手机预览，检查目录、圆角、引用、高亮、结语、图片与深色模式。

## 文件入口：Agent 与浏览器复用同一套排版

```sh
node scripts/render.mjs article.md --out output/new-article --theme huasan-claude
node scripts/render.mjs article.md --out output/forest-article --theme huasan-forest
```

此入口只用保真模式，不调用 LLM；输出目录须为空，存在未决批注时停止。不再接受 `--cover` 参数。

输出 `article.md`、`article-body.html`、`preview.html`、`check.json`。预览页的复制功能需要 localhost/HTTPS；本地生成不等于作者确认或公众号实测通过。

## 开发与源码导航

```sh
npm test          # 保真渲染与个人主题纯换色一致性
npm run build    # TypeScript 检查与生产构建，输出 dist/
npm run preview  # 本地查看构建结果
```

| 要改什么 | 文件 |
|---|---|
| 保真模式的看点、章节编号、THE END、END | [`src/core/faithful.ts`](src/core/faithful.ts) |
| 结语识别词与内置英文标签 | [`src/core/transform.ts`](src/core/transform.ts) |
| 增强模式的目录、引言、封面与文末组装 | [`src/core/generator.ts`](src/core/generator.ts) |
| 个人配色 | [`src/themes/huasan.ts`](src/themes/huasan.ts) |
| 基础组件及目录卡片等高 | [`src/themes/base.ts`](src/themes/base.ts) |
| 主题注册与默认主题 | [`src/themes/index.ts`](src/themes/index.ts) |
| LLM 提示词与分析编排 | [`src/ai/prompts.ts`](src/ai/prompts.ts)、[`src/ai/enhance.ts`](src/ai/enhance.ts) |
| 实时渲染与剪贴板 | [`src/stores/editor.ts`](src/stores/editor.ts) |
| 本地文件渲染 | [`scripts/render.mjs`](scripts/render.mjs) |

主题源码和应用使用 Vue 3、TypeScript、Pinia、markdown-it、Tailwind CSS 和 Vite。构建产物可由静态服务器托管；本仓库保留上游 Dockerfile 与 docker-compose 配置。本文没有声明已完成线上部署或所有服务商的 LLM 实测。
